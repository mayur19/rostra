# Requirements

Priorities use MoSCoW (**M**ust, **S**hould, **C**ould, **W**on't this release). Status is
`done` when implemented and covered by automated tests, otherwise `pending`. Ticket mapping is
in [requirements-traceability.md](requirements-traceability.md).

## Functional requirements

### Identity & access (E1)

| ID     | Requirement                                                                       | Priority | Acceptance criteria                                                                                                                                                                                                                                                                                                                                 | Status  |
| ------ | --------------------------------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| FR-001 | A visitor can register an organization and its owner account.                     | M        | POST `/auth/register` with org name, name, email, password (>= 12 chars) and time zone creates the organization, an `owner` user and a session; a duplicate email returns the uniform 400 `REGISTRATION_FAILED`; more than `REGISTER_RATE_LIMIT_MAX` registrations per IP per window return 429.                                                    | done    |
| FR-002 | Users log in with email and password.                                             | M        | Valid credentials return 200 and set an HttpOnly `rostra_session` cookie and a readable `rostra_csrf` cookie; invalid credentials return 401 `INVALID_CREDENTIALS` without revealing which part was wrong.                                                                                                                                          | done    |
| FR-003 | Users can log out.                                                                | M        | POST `/auth/logout` deletes the server-side session and clears both cookies; reusing the old cookie returns 401.                                                                                                                                                                                                                                    | done    |
| FR-004 | A signed-in user can read their profile, organization and permissions.            | M        | GET `/auth/me` returns user, organization, role permissions and the session CSRF token.                                                                                                                                                                                                                                                             | done    |
| FR-005 | Mutating requests are protected against CSRF.                                     | M        | POST/PUT/PATCH/DELETE without a matching `x-csrf-token` header and `rostra_csrf` cookie (and, when signed in, the session token) return 403 `CSRF_FAILED`.                                                                                                                                                                                          | done    |
| FR-006 | Repeated failed logins are throttled.                                             | M        | Three limiters return 429 with `Retry-After`: per IP+email (`LOGIN_RATE_LIMIT_MAX` per window), per IP against password spraying (`LOGIN_IP_RATE_LIMIT_MAX`), and per email progressive backoff after `LOGIN_EMAIL_FREE_ATTEMPTS` failures (doubling from `LOGIN_EMAIL_BACKOFF_BASE_MS`, capped at `LOGIN_EMAIL_BACKOFF_MAX_MS`, reset on success). | done    |
| FR-007 | Access is controlled by role permissions.                                         | M        | Roles owner/admin/scheduler/manager/employee map to fixed permissions; a `manager` calling POST `/rosters/{id}/solve` gets 403.                                                                                                                                                                                                                     | done    |
| FR-008 | Security-relevant actions are written to an audit log and can be read.            | M        | Registration, login, logout, skill/employee/roster/shift changes, solves and assignment replacements create audit rows; GET `/audit-logs` (audit:read) pages them newest first.                                                                                                                                                                     | done    |
| FR-009 | Owners manage organization settings.                                              | S        | GET/PATCH `/organization` reads and updates name, default time zone and week start day.                                                                                                                                                                                                                                                             | pending |
| FR-010 | Admins invite users through an in-app outbox and invitees accept.                 | S        | Invitation creates a single-use token valid 7 days; acceptance sets password and role.                                                                                                                                                                                                                                                              | pending |
| FR-011 | Admins change roles and deactivate users.                                         | S        | Deactivated users cannot log in and their sessions are revoked.                                                                                                                                                                                                                                                                                     | pending |
| FR-012 | Users can reset forgotten passwords.                                              | S        | Single-use, 30-minute token delivered via outbox; all sessions revoked on reset.                                                                                                                                                                                                                                                                    | pending |
| FR-014 | Self-service signup verifies the email address before the account becomes usable. | S        | Registration always answers uniformly; a verification token sent via the local outbox activates the account.                                                                                                                                                                                                                                        | pending |
| FR-013 | Users list and revoke their sessions; idle and absolute timeouts apply.           | C        | Revoked session returns 401 on next request.                                                                                                                                                                                                                                                                                                        | pending |

### Workforce model (E2)

| ID     | Requirement                                                                              | Priority | Acceptance criteria                                                                                                                      | Status  |
| ------ | ---------------------------------------------------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| FR-020 | Schedulers define skills per organization.                                               | M        | POST `/skills` with an upper-case code (2-32 chars) and name; duplicate code returns 409.                                                | done    |
| FR-021 | Schedulers create employees with contract terms, skills, preferences and unavailability. | M        | POST `/employees` validates min <= max hours, 1-7 consecutive days, 0-24 rest hours; unknown skill codes return 422.                     | done    |
| FR-022 | Employees can be listed with pagination and read individually.                           | M        | GET `/employees?limit&offset` returns `meta.total`; GET `/employees/{id}` returns 404 for other tenants' ids.                            | done    |
| FR-023 | Employees can be partially updated.                                                      | M        | PATCH merges fields, revalidates the full record and increments `version`.                                                               | done    |
| FR-024 | Skill grants carry an optional expiry date.                                              | M        | A grant expiring before a shift's local date makes that assignment a `SKILL_EXPIRED` hard violation; expiring on the day is still valid. | done    |
| FR-025 | Locations with their own time zone can be managed.                                       | S        | Each roster belongs to a location and inherits its zone.                                                                                 | pending |
| FR-026 | Departments and department-scoped permissions.                                           | S        | A scheduler scoped to a department sees only its employees and rosters.                                                                  | pending |
| FR-027 | Positions define required skills and default rates.                                      | C        | Creating an employee in a position pre-fills skills and rate.                                                                            | pending |
| FR-028 | Contracts are versioned with effective dates.                                            | S        | Solving a week uses the contract version effective on `weekStart`.                                                                       | pending |
| FR-029 | Employees can be archived and imported from CSV.                                         | S        | Archived employees disappear from solving; CSV import reports row-level errors without partial writes.                                   | pending |
| FR-030 | Expiring certifications are reported.                                                    | S        | Report lists grants expiring within N days by employee and skill.                                                                        | pending |

### Demand & coverage (E3)

| ID     | Requirement                                                                 | Priority | Acceptance criteria                                                                                                                                     | Status  |
| ------ | --------------------------------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| FR-040 | Weekly shift templates expand into concrete shifts DST-safely.              | M        | `expandTemplates` resolves start and end from local wall time independently: a 22:00-06:00 night is 7 h across spring-forward and 9 h across fall-back. | done    |
| FR-041 | Shift templates can be stored and applied to a roster via API.              | S        | POST `/rosters/{id}/shifts/from-templates` creates the week's shifts.                                                                                   | pending |
| FR-042 | Historical volumes can be imported per location and interval.               | S        | CSV with timestamp, location, volume; duplicates rejected.                                                                                              | pending |
| FR-043 | Demand is forecast in-house from history.                                   | S        | Moving average plus weekday/hour seasonal indices; backtest MAPE reported.                                                                              | pending |
| FR-044 | Coverage requirements per 15-minute interval convert workload to headcount. | S        | Requirement curve editable and persisted per location and skill.                                                                                        | pending |
| FR-045 | Shift demand can be derived from a coverage curve.                          | C        | Interval-covering heuristic produces shifts whose summed headcount meets every interval with minimal excess.                                            | pending |

### Solver & rules (E4)

| ID     | Requirement                                                                                                                                                       | Priority | Acceptance criteria                                                                                                                                                           | Status  |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| FR-050 | Schedulers create weekly rosters in a time zone.                                                                                                                  | M        | POST `/rosters` with name, `weekStart` (YYYY-MM-DD) and IANA zone (normalized to its canonical name).                                                                         | done    |
| FR-051 | Schedulers add and remove shift demand on draft rosters.                                                                                                          | M        | POST `/rosters/{id}/shifts` rejects shifts starting outside the seven local days (422), longer than 16 h, or with unknown skills; DELETE removes a shift and its assignments. | done    |
| FR-052 | The system produces a roster automatically.                                                                                                                       | M        | POST `/rosters/{id}/solve` runs greedy construction and simulated annealing, stores assignments and a solver run, and returns the schedule with evaluation.                   | done    |
| FR-053 | Solving is reproducible.                                                                                                                                          | M        | Same roster data, seed and iteration budget yield identical assignments and scores.                                                                                           | done    |
| FR-054 | Hard rules: coverage, skill, certification expiry, unavailability, overlap, minimum rest, maximum weekly hours, maximum consecutive days, maximum shifts per day. | M        | Each rule detected with a penalty proportional to its magnitude; a roster is `feasible` only with zero hard penalty.                                                          | done    |
| FR-055 | Soft rules: contracted minimum hours, preferred days off, night avoidance, overtime, fairness.                                                                    | M        | Each contributes to the soft score; fairness is the variance of utilization across staff with a minimum.                                                                      | done    |
| FR-056 | Every violation is explainable.                                                                                                                                   | M        | Violations carry constraint id, severity, penalty, employee, shift ids and a human-readable message, sorted hard first then by penalty.                                       | done    |
| FR-057 | Manual choices can be pinned and survive re-solving.                                                                                                              | M        | Assignments saved with `pinned: true` are kept when solving with `keepPinned` (default true).                                                                                 | done    |
| FR-058 | Solver run history is kept per roster.                                                                                                                            | S        | GET `/rosters/{id}/solver-runs` lists seed, iterations, greedy and final scores, coverage and elapsed time.                                                                   | done    |
| FR-059 | The constraint catalog and default weights are discoverable.                                                                                                      | S        | GET `/constraints` returns all 14 rules with severity and unit.                                                                                                               | done    |
| FR-060 | Long solves run as background jobs with progress and cancellation.                                                                                                | S        | Job status endpoint reports iteration progress and best score; cancel stops within 1 s.                                                                                       | pending |
| FR-061 | "Why can't X work Y?" explanations.                                                                                                                               | S        | Endpoint lists the rules that would be violated by a hypothetical assignment.                                                                                                 | pending |
| FR-062 | Jurisdiction labor rule sets (daily overtime, breaks, minors, night limits).                                                                                      | S        | Rule sets attach to locations; evaluators load them as data.                                                                                                                  | pending |
| FR-063 | Rest and consecutive-day rules span roster boundaries.                                                                                                            | S        | Last days of the previous week are considered.                                                                                                                                | pending |
| FR-064 | Organizations tune constraint weights.                                                                                                                            | C        | PUT `/constraint-weights` changes the penalties used by subsequent solves.                                                                                                    | pending |

### Schedule editing & publish (E5)

| ID     | Requirement                                                     | Priority | Acceptance criteria                                                                                                                                              | Status  |
| ------ | --------------------------------------------------------------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| FR-070 | Users view a roster as a week grid with violations.             | M        | GET `/rosters/{id}/schedule` returns roster, shifts, employees, assignments and evaluation; the UI renders employees x days with a violations panel and metrics. | done    |
| FR-071 | Proposed edits are evaluated without saving.                    | M        | POST `/rosters/{id}/evaluate` returns the evaluation of an arbitrary assignment set; unknown ids or over-headcount return 422.                                   | done    |
| FR-072 | Manual edits replace assignments atomically.                    | M        | PUT `/rosters/{id}/assignments` validates, replaces all assignments in one transaction and records an audit entry; non-draft rosters return 409.                 | done    |
| FR-073 | Rosters are published as immutable versions with notifications. | M        | Publishing freezes a version, notifies affected employees in-app, and later edits create a new draft.                                                            | pending |
| FR-074 | Drag-and-drop editing with live feedback.                       | S        | Dropping a shift on an employee updates violations within 200 ms.                                                                                                | pending |
| FR-075 | Roster versions, undo/redo and optimistic concurrency.          | S        | Stale `version` on save returns 409 with the current version.                                                                                                    | pending |
| FR-076 | Employees see their own schedule and subscribe via iCalendar.   | S        | Signed, revocable feed URL.                                                                                                                                      | pending |

## Non-functional requirements

| ID      | Category        | Requirement                                                      | Priority | Acceptance criteria                                                                                                                                       | Status  |
| ------- | --------------- | ---------------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------- |
| NFR-001 | Performance     | Solve a 160-employee, 544-slot week with 50k iterations quickly. | M        | < 5 s in the automated test (`solve.test.ts`); ~0.2-0.4 s on a laptop via `npm run bench`.                                                                | done    |
| NFR-002 | Performance     | Read endpoints respond fast.                                     | M        | p95 < 150 ms for schedule GET of a 20-employee ward on a 2 vCPU VM.                                                                                       | pending |
| NFR-003 | Determinism     | Solver output depends only on input, seed and iteration budget.  | M        | Repeat runs produce deep-equal results (tests).                                                                                                           | done    |
| NFR-004 | Correctness     | DST and time-zone safety.                                        | M        | Tests cover spring-forward gaps, fall-back overlaps and overnight shifts.                                                                                 | done    |
| NFR-005 | Security        | Passwords hashed with scrypt (N=16384, r=8, p=1, 16-byte salt).  | M        | No plaintext or reversible storage; constant-time compare.                                                                                                | done    |
| NFR-006 | Security        | Session tokens stored only as HMAC-SHA256 hashes.                | M        | DB rows cannot be replayed as cookies.                                                                                                                    | done    |
| NFR-007 | Security        | Tenant isolation on every query.                                 | M        | Cross-tenant ids return 404 (integration test).                                                                                                           | done    |
| NFR-008 | Security        | Input validated with zod at every boundary.                      | M        | Invalid payloads return 422 with field paths.                                                                                                             | done    |
| NFR-009 | Security        | Bounded resource use from user input.                            | M        | Body limit 1 MiB, iteration cap (`SOLVER_MAX_ITERATIONS`), formatter cache keyed by canonical zone names, rate limiter key cap.                           | done    |
| NFR-021 | Security        | Client IPs are derived only from trusted proxies.                | M        | `TRUST_PROXY` accepts `false`, a hop count or a list of proxy IPs/CIDRs; `true` is rejected so arbitrary `X-Forwarded-For` values cannot evade IP limits. | done    |
| NFR-010 | Reliability     | Writes to a roster are serialized.                               | M        | Solve and edits lock the roster row (`SELECT ... FOR UPDATE`).                                                                                            | done    |
| NFR-011 | Observability   | Structured JSON logs with request ids; secrets redacted.         | M        | `x-request-id` echoed; cookies and CSRF headers redacted.                                                                                                 | done    |
| NFR-012 | Operability     | One-command local setup.                                         | M        | `./run.sh setup` on a clean clone with local PostgreSQL succeeds.                                                                                         | done    |
| NFR-013 | Maintainability | Strict TypeScript, lint and format gates in CI.                  | M        | CI runs lint, format:check, typecheck, test, build on every push.                                                                                         | done    |
| NFR-014 | Testability     | Coverage >= 80% lines on implemented code.                       | M        | Vitest thresholds in each workspace.                                                                                                                      | done    |
| NFR-015 | Portability     | No external services at runtime; native PostgreSQL only.         | M        | No outbound network calls in code.                                                                                                                        | done    |
| NFR-016 | Data            | Money as integer minor units; instants as `timestamptz` UTC.     | M        | Schema review.                                                                                                                                            | done    |
| NFR-017 | Accessibility   | Week grid and forms meet WCAG 2.2 AA.                            | S        | Keyboard navigation and screen-reader labels verified.                                                                                                    | pending |
| NFR-018 | Scalability     | 500 staff x 4 weeks solved under 30 s.                           | S        | Benchmark in CI on reference hardware.                                                                                                                    | pending |
| NFR-019 | Recoverability  | RPO 24 h, RTO 1 h with nightly `pg_dump` and a tested restore.   | S        | Quarterly restore drill logged.                                                                                                                           | pending |
| NFR-020 | Usability       | Violation messages readable without training.                    | S        | Every message names the employee, shift(s) and limit.                                                                                                     | done    |
