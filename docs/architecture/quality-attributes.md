# Quality attributes

Each attribute has a measurable target, the mechanism that achieves it and how it is
verified. Status: **met** (verified automatically today), **partial**, or **planned**.

| Attribute                           | Scenario                                                       | Target                                                                        | Mechanism                                                                                      | Verification                                      | Status  |
| ----------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------- | ------- |
| Solver performance                  | Scheduler solves a 160-employee, 544-slot week, 50k iterations | < 5 s (CI), ~0.2-0.4 s laptop                                                 | Incremental per-employee rescoring, precomputed static eligibility, flat arrays                | `solve.test.ts` performance test; `npm run bench` | met     |
| Solver quality                      | Seeded ward roster (20 staff, 68 slots)                        | 100% coverage, hard score 0, soft <= greedy                                   | Most-constrained-first greedy, annealing with reassign + swap moves                            | `solve.test.ts`                                   | met     |
| Determinism                         | Re-solve with same seed and budget                             | Identical assignments and scores                                              | mulberry32 PRNG, iteration budget (not wall clock), stable ordering                            | `solve.test.ts`, `rng.test.ts`                    | met     |
| Time correctness                    | Shifts across DST changes and midnight                         | Correct real duration; correct local day                                      | `zonedToUtc` with gap/overlap resolution; local day per shift start                            | `zoned.test.ts`, `templates.test.ts`              | met     |
| Explainability                      | Any violation shown to a user                                  | Names employee, shift(s), limit                                               | Violation sink in evaluators                                                                   | `evaluate.test.ts` message assertions             | met     |
| Incremental correctness             | Thousands of random moves                                      | Incremental score == full evaluation (soft within 1 due to float aggregation) | `SearchState` rescoring + O(1) fairness aggregate                                              | `state.test.ts`                                   | met     |
| API latency                         | GET schedule for 20 staff                                      | p95 < 150 ms on 2 vCPU                                                        | Few queries, JSON aggregation in SQL                                                           | Load test (RO-243)                                | planned |
| Availability                        | Single VM                                                      | 99.5% monthly                                                                 | systemd restart, readiness probe `/api/v1/ready`                                               | Uptime monitoring                                 | planned |
| Security: authentication            | Credential stuffing / spraying                                 | Throttled per IP+email, per IP, per email backoff                             | In-process limiters (ADR-0006)                                                                 | `auth.test.ts`                                    | met     |
| Security: session theft via DB leak | Attacker reads `sessions`                                      | Cannot forge cookie                                                           | HMAC-SHA256 token hash with `SESSION_SECRET`                                                   | Code review, `auth.test.ts`                       | met     |
| Security: CSRF                      | Cross-site form post                                           | Rejected                                                                      | Double-submit token bound to session                                                           | `auth.test.ts`                                    | met     |
| Isolation                           | Tenant B requests tenant A's employee id                       | 404                                                                           | `organization_id` predicate in every repository query                                          | `employees.test.ts`, `rosters.test.ts`            | met     |
| Resource bounds                     | Hostile inputs                                                 | No unbounded memory or CPU                                                    | Body 1 MiB, iteration cap, canonical zone cache, limiter key cap, 16 h max shift, 50 headcount | Unit + integration tests                          | met     |
| Consistency                         | Concurrent solve and manual edit                               | Serialized, no lost writes                                                    | `SELECT ... FOR UPDATE` on roster row inside transaction                                       | `rosters.test.ts` concurrent solve                | met     |
| Maintainability                     | Any change                                                     | Lint, format, strict typecheck, tests green                                   | CI pipeline                                                                                    | `.github/workflows/ci.yml`                        | met     |
| Test coverage                       | Implemented code                                               | >= 80% lines (shared at 100%)                                                 | Vitest v8 thresholds                                                                           | `npm run test:coverage`                           | met     |
| Recoverability                      | DB loss                                                        | RPO 24 h, RTO 1 h                                                             | Nightly `pg_dump -Fc`, restore runbook                                                         | Restore drill (RO-242)                            | partial |
| Accessibility                       | Keyboard-only scheduler                                        | WCAG 2.2 AA                                                                   | Semantic table grid, labels                                                                    | Audit (RO-240)                                    | planned |
| Scalability                         | 500 staff x 4 weeks                                            | < 30 s                                                                        | Async jobs, multi-start, tabu (RO-160, RO-164, RO-241)                                         | Benchmark                                         | planned |
